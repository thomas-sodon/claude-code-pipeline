## Assumptions to review

- The wider asking is the default and there is no new dial for it: `on_question: 'assume'` stays the only way to proceed without answers (this session, in the spec).
- Who decided is a closed tag on each D-record heading, `(person, <date>[, <ref>])`, `(source)` or `(assumed)`; the lint only warns on a missing or malformed one, so older docs keep passing.
- A design run saves the answers it was given, and the Intake's assumptions, to `design/answers.json` on the state branch (as visible as the repository) unless the person said no at /start-product (`save_answers: false`); the builder framing goes there only on a yes to the same consent question.
- A name, a licence, and an org or bundle id are asked and recorded as decisions; they are no longer decision gates before Bootstrap.
- A decision the person confirms when shown the unconfirmed ones is recorded by editing its tag to `(person, <today>, edit)`, with no re-run; a change goes back as an answer.
- A corrected line of a PR's `## Assumptions to review` is a review comment that /process-comments applies, not an answer to a re-run.
- In brief mode every answer reaches every author and reviewer of the design run; an answer id is never reused (the run stops and names the next free number).
- `max_milestones: 0` means no proposal; plan-to-merged-pr restores a branch's saved plan on a re-run unless `replan: true`.
- The lane workflows refuse an `{ id: answer }` map with keys and an answer whose lane the run does not have, instead of dropping them.
